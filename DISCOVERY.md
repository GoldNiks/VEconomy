## 3. Существующая система экономики (старый прототип)

Этот же проект содержит прототип экономики. Он **не является** готовым плагином для миграции; это ранняя версия ядра, которую предстоит переписать под архитектуру ТЗ. Характеристики старого кода:

| Аспект | Старый прототип | Требование ТЗ | Вердикт |
|---|---|---|---|
| Денежный тип | `double` (`EconomyAPI.getBalance(): double`) | `long`, минимальные единицы | **переписать** |
| Хранилище | JSON `world/economy/balances.json` + capability NBT `.dat` | SQLite/БД, репозиторий | **переписать** |
| Ledger | Лог-файл `logs/economy_transactions.log` | Таблица `transactions` | **переписать** |
| Команды | `/economy balance|pay|set|add|reset|reload|top` | `/money`, `/pay`, `/economy admin` | **переписать** |
| UUID-политика | BalanceStore по UUID, имя только для поиска | UUID — источник истины | сохранить принцип |
| Идемпотентность | нет | обязательна | добавить |
| Отчётность/аудит | нет | ledger + аудит | добавить |

Вывод: старую систему **не удаляем молча и не сохраняем как основную** — она противоречит денежной модели ТЗ (`double` запрещён) и не собирается. Вместо этого ядро переписывается под ТЗ, а данные старого хранилища (`world/economy/balances.json`) **импортируются в SQLite** при первом старте (см. `MIGRATION.md`). Старый JSON больше не пишется.

## 5. Зависимости и интеграции

- В `build.gradle` нет зависимостей на FTB Quests, FTB Teams, KubeJS, GregTech, TerraFirmaCraft — мод ядра чистый Forge. Это правильно: ядро должно работать без FTB.
- Нужно добавить: SQLite JDBC (`org.xerial:sqlite-jdbc`) — единственная внешняя библиотека.
- Каталог модпака TerraFirmaGreg Modern / конфиги FTB в этом рабочем каталоге **отсутствуют** — интеграции FTB Quests/KubeJS откладываются до отдельного этапа (изучение API по реальным файлам сборки).

## 6. Server-only

- Мод пишется как серверный: без клиентских классов, без обязательных пакетов.
- В `mods.toml` выставлен `side="SERVER"` — клиент не обязан ставить мод.
- **Не подтверждено** тестовым подключением (требуется реальная проверка на целевом сервере) — это отмечено как открытый пункт в `README.md`.

## 7. Решения, принятые на основе исследования

1. Полностью переписать ядро под архитектуру ТЗ (long/minor, SQLite, ledger, идемпотентность).
2. Сохранить существующие имя/пакет/mod id.
3. База: SQLite, файл `world/economy/valoreconomy.db` (путь совместим с существующим каталогом `world/economy/`, документирован в README).
4. Казна — системный аккаунт с фиксированным UUID (в той же таблице `accounts`).
5. Одноразовый импорт `world/economy/balances.json` при первом запуске новой БД.

## 8. Блокировки

- Отсутствуют файлы целевого модпака (TFG, FTB) для проверки API интеграций — интеграции не реализуются на этом этапе.
- Проверка «клиент без мода может подключиться к серверу с модом» возможна только на целевом сервере.
