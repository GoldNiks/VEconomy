# Денежные награды VEconomy в FTB Quests

Эта инструкция описывает рекомендуемый вариант: игрок видит сумму прямо в окне
квеста, а указанная сумма является **общим фондом команды**, а не выплатой каждому
участнику.

## 1. Подготовка VEconomy

На сервере должны быть установлены VEconomy, FTB Quests и FTB Teams. Отдельные
права LuckPerms игрокам выдавать не нужно.

Проверьте файл:

`config/VMods/VEconomy/veconomy-quests.json`

Для квестов с видимой Command Reward в этом файле не должно быть автоматической
награды. Безопасная основа:

```json
{
  "customRewardEnabled": true,
  "defaultPerQuest": 0,
  "chapters": {},
  "quests": {}
}
```

Особенно важно:

- `defaultPerQuest` должен быть `0`;
- ID настраиваемого квеста не должен присутствовать в `quests`;
- название его главы не должно присутствовать в `chapters`.

После изменения файла выполните `/economy admin reload` или перезапустите сервер.
`customRewardEnabled` относится к старому типу Custom Reward и не мешает новой
Command Reward.

## 2. Создание награды в FTB Quests

1. Откройте редактор FTB Quests и выберите нужный квест.
2. В секции наград нажмите добавление награды.
3. Выберите встроенный тип **Command Reward** / **Командная награда**.
4. Откройте настройки созданной награды и заполните поля:

| Поле FTB Quests | Значение |
|---|---|
| `Title` / `Название` | `⛃50` |
| `Command` / `Команда` | `/economy quest-reward {quest}` |
| `Team Reward` / `Командная награда` | включено |
| `Elevate Permissions` / `Повысить права` | включено |
| `Silent` / `Без вывода` | включено |

Значок награды можно выбрать любой, например монету. На размер выплаты он не
влияет.

Сохраните изменения FTB Quests. Команду нужно вводить именно с `{quest}` — FTB
Quests сам заменит этот шаблон стабильным ID текущего квеста.

## 3. Как задаётся сумма

Сумма берётся только из видимого поля `Title`. Допустимы:

- `⛃50`;
- `50`;
- `⛃25,50` или `⛃25.50`, если в VEconomy используются дробные единицы.

Текст вроде `Награда: ⛃50` не допускается. Это сделано специально, чтобы другая
командная награда со случайным числом в названии не создала деньги.

В одном квесте должна быть ровно одна Command Reward с денежным названием. Другие
Command Reward допустимы, только если их названия не выглядят как сумма VEconomy.

## 4. Как делится общий фонд

VEconomy берёт всех текущих участников FTB Teams, включая тех, кто сейчас не в
сети, и делит фонд поровну:

```text
Фонд ⛃50, один участник  → игрок получает ⛃50
Фонд ⛃50, два участника  → каждый получает ⛃25
Фонд ⛃50, три участника  → каждый получает ⛃16, остаток ⛃2 уходит в казну
```

Таким образом, увеличение команды не увеличивает общую эмиссию. Если фонд меньше
числа участников в минимальных денежных единицах, выдача отклоняется: каждому
участнику должна доставаться хотя бы одна минимальная единица.

## 5. Что происходит при получении награды

Когда игрок нажимает получение награды, VEconomy:

1. получает от FTB Quests только ID квеста;
2. проверяет, что команду вызвал игрок;
3. проверяет завершение квеста его FTB-командой;
4. находит денежную Command Reward и проверяет `Team Reward`;
5. читает фонд из её `Title`;
6. проверяет отсутствие JSON-автоначисления;
7. начисляет доли всем участникам и остаток казне;
8. записывает отдельные идемпотентные ключи, исключающие повторную выплату.

Сумма и UUID получателя не передаются в команде, поэтому игрок не может подменить
их через плейсхолдеры FTB Quests. `Elevate Permissions` даёт команде временный
уровень 2 только на момент запуска награды; постоянные права игроку не выдаются.

## 6. Проверка на тестовом квесте

1. Создайте простой тестовый квест и Command Reward с `Title = ⛃30`.
2. Укажите команду `/economy quest-reward {quest}` и включите три переключателя
   из таблицы выше.
3. Объедините двух тестовых игроков в одну FTB-команду.
4. Зафиксируйте их балансы через `/money`.
5. Завершите квест и заберите награду одним из участников.
6. Проверьте: баланс каждого участника должен увеличиться на `⛃15`.
7. Повторная попытка не должна создать деньги ещё раз.

В серверном логе успешная выдача выглядит примерно так:

```text
FTB Quests: distributed common fund 30 for quest ... among 2 team members (15 each, 0 to treasury)
```

## 7. Частые ошибки

| Статус в сообщении или логе | Причина |
|---|---|
| `QUEST_NOT_COMPLETED` | Квест не завершён командой игрока |
| `INVALID_REWARD_SETUP` | Не включён Team Reward, неверный Title, несколько денежных Command Reward или фонд слишком мал |
| `AUTO_REWARD_CONFLICT` | Для квеста действует награда из `veconomy-quests.json` |
| `TEAM_NOT_FOUND` | FTB Teams не вернул команду или в ней нет участников |
| `ALREADY_DISTRIBUTED` | Выплата с этими идемпотентными ключами уже проводилась |
| `PARTIAL_FAILURE` | Одна из операций начисления была отклонена; подробности находятся рядом в серверном логе |

Если команда вообще не запускается, в первую очередь проверьте
`Elevate Permissions`. Если игрок видит служебный ответ команды в чате — включите
`Silent`.

После устранения причины `PARTIAL_FAILURE` администратор может безопасно повторить
обработку от имени участника завершившей квест команды:

```text
/execute as <игрок> run economy quest-reward <ID_квеста>
```

Уже успешные начисления будут пропущены по идемпотентным ключам, а ранее
отклонённые операции выполнятся повторно. ID квеста можно взять в редакторе FTB
Quests или из строки ошибки в серверном логе.

## 8. Что не следует использовать

Не указывайте команды `/money give`, `/economy add` или команды с `{p}`. Для этой
интеграции единственная правильная команда:

```text
/economy quest-reward {quest}
```

Старый тип FTB Quests Custom Reward по-прежнему поддерживается, но начисляет сумму
забирающему игроку и не реализует описанный общий фонд. Для новых квестов
используйте Command Reward.
