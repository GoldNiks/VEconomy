# Миграция: старый прототип → новое ядро

## Как было (старый прототип)

Старый прототип хранил баланс игрока в capability (NBT в `.dat` игрока) и в кеше
`HashMap<UUID, Double>` с записью в `logs/economy_transactions.log`. Деньги были `double`,
что приводило к потере точности; синхронизация с клиентом шла пакетами.

Эти механизмы **удалены**: пакеты `capability`, `network`, `storage` больше не существуют.
Мод теперь серверный (`side="SERVER"`).

## Как стало

Все балансы — `long` в минимальных единицах, хранятся в SQLite-базе
`<мир>/economy/valoreconomy.db` (по умолчанию `economy/valoreconomy.db` относительно
каталога мира). Схема версионируется через `PRAGMA user_version`.

## Перенос старых балансов

Если в каталоге мира лежит файл `balances.json` в формате
`{"balances": {"<uuid>": <double>}}`, при первом старте сервера он будет импортирован
автоматически:

- каждая сумма переводится из `double` в минимальные единицы с округлением
  (`Math.round(value * 10^decimalPlaces)`);
- для каждого игрока создаётся аккаунт и запись журнала типа `LEGACY_IMPORT`;
- некорректные UUID и неположительные суммы пропускаются;
- импорт выполняется только один раз (флаг `legacy_import_done` в таблице `meta`).

После успешного импорта файл можно удалить.

> Файл должен называться `balances.json` и лежать рядом с базой, т.е.
> в каталоге `<мир>/economy/`.

## Что нельзя сделать автоматически

- Строки в `logs/economy_transactions.log` не переносятся в журнал транзакций —
  импортируется только итоговый баланс.
- Старые значения с дробной частью при `decimalPlaces = 0` округляются.

## Обновление в будущем

Для изменения схемы БД добавляйте новую миграцию в
`MigrationManager.MIGRATIONS` и поднимайте номер версии; миграции выполняются
транзакционно и безопасны для повторного запуска.
